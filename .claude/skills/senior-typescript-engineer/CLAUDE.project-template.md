# Project Instructions

Use the `senior-typescript-engineer` skill for TypeScript implementation, review, refactoring, debugging and architecture decisions.

## Project rules

- Inspect existing code before modifying it.
- Preserve current architecture and public contracts unless the task explicitly requires a change.
- Prefer the smallest coherent modification.
- TypeScript strict; avoid `any`.
- Apply SOLID pragmatically.
- Use design patterns only for concrete problems.
- Follow KISS and YAGNI.
- Consider Green Software/resource efficiency.
- Do not refactor unrelated code.
- Run the project's available type-check, tests and lint after modifications.
- Never claim a validation passed unless it was actually executed successfully.

## Task completion

Report:
- meaningful changes
- engineering decisions
- validations actually executed
- remaining risks
